# Чек-лист тестирования функциональных требований (Checklist)
**Проект:** `property-view-api`  
**Связанная спецификация:** [docs/SRS.md](SRS.md)

Проверки сгруппированы по модулям приложения. Для каждого функционального требования (`FR-01`..`FR-18`) предусмотрены как позитивные (`[+]`), так и негативные (`[-]`) проверки.

---

## Модуль 1: Маршрутизация, контекст приложения и OpenAPI (`Presentation / Config`)

### FR-01: Доступность API под префиксом `/property-view` на порту `8092`
- `[+]` **CL-01.1 (Позитивная):** Запрос `GET http://localhost:8092/property-view/hotels` успешно обрабатывается и возвращает `200 OK`.
- `[-]` **CL-01.2 (Негативная):** Запрос без контекстного префикса `GET http://localhost:8092/hotels` отклоняется со статусом `404 Not Found`.
- `[-]` **CL-01.3 (Негативная):** Обращение к несуществующему пути внутри контекста `GET /property-view/unknown-endpoint` возвращает `404 Not Found`.

### FR-18: Доступность OpenAPI, Swagger UI и веб-клиента каталога
- `[+]` **CL-18.1 (Позитивная):** Запрос `GET /property-view/v3/api-docs` возвращает `200 OK` и валидный JSON-документ OpenAPI 3.0 со всеми маршрутами.
- `[+]` **CL-18.2 (Позитивная):** Запрос `GET /property-view/swagger-ui.html` (с редиректом) и `GET /property-view/index.html` возвращают `200 OK` и HTML-интерфейс.
- `[-]` **CL-18.3 (Негативная):** Попытка вызвать `POST` на статический ресурс `/property-view/index.html` возвращает ошибку метода (`405 Method Not Allowed` / `404`).

## Модуль 2: Управление отелями (`Presentation: HotelController` & `Application: CreateHotelService / HotelQueryService`)

### FR-02: Получение краткого списка всех отелей (`GET /property-view/hotels`)
- `[+]` **CL-02.1 (Позитивная):** При пустой БД запрос `GET /property-view/hotels` возвращает `200 OK` и пустой массив `[]`.
- `[+]` **CL-02.2 (Позитивная):** При наличии нескольких отелей возвращается массив кратких карточек (`id`, `name`, `description`, `address`, `phone`), отсортированный по возрастанию `id`.
- `[-]` **CL-02.3 (Негативная):** Отправка неподдерживаемого HTTP-метода `PUT /property-view/hotels` или `DELETE /property-view/hotels` возвращает ошибку `405 Method Not Allowed`.

### FR-03: Форматирование адреса в одну строку в кратком представлении (`Domain: Address`)
- `[+]` **CL-03.1 (Позитивная):** Адрес `{houseNumber: 9, street: "Pobediteley Avenue", city: "Minsk", postCode: "220004", country: "Belarus"}` форматируется ровно в `"9 Pobediteley Avenue, Minsk, 220004, Belarus"`.
- `[-]` **CL-03.2 (Негативная):** Создание `Address` с `houseNumber <= 0` или пустой строкой `street`/`city`/`country`/`postCode` выбрасывает `DomainValidationException`.

### FR-04: Получение полной карточки отеля по ID (`GET /property-view/hotels/{id}`)
- `[+]` **CL-04.1 (Позитивная):** Запрос `GET /property-view/hotels/1` для существующего отеля возвращает `200 OK` и полный JSON (`id`, `name`, `description`, `brand`, вложенные `address`, `contacts`, `arrivalTime`, массив `amenities`).
- `[-]` **CL-04.2 (Негативная):** Запрос с нечисловым идентификатором `GET /property-view/hotels/abc` возвращает `400 Bad Request`.

### FR-05: Обработка несуществующего ID отеля (`404 Not Found`)
- `[+]` **CL-05.1 (Позитивная проверка контракта ошибки):** При отсутствии отеля возвращается `Content-Type: application/problem+json` с полями `title: "Hotel not found"` и `status: 404`.
- `[-]` **CL-05.2 (Негативная):** Запрос `GET /property-view/hotels/999999` для несуществующего `id` возвращает `404 Not Found`.
- `[-]` **CL-05.3 (Негативная):** Запрос `POST /property-view/hotels/999999/amenities` с валидным массивом `["WiFi"]` для несуществующего `id` возвращает `404 Not Found`.

### FR-06: Создание нового отеля (`POST /property-view/hotels`)
- `[+]` **CL-06.1 (Позитивная):** Отправка полного валидного JSON создаёт отель с `id >= 1`, возвращает `201 Created`, заголовок `Location: .../property-view/hotels/{id}` и краткую карточку.
- `[-]` **CL-06.2 (Негативная):** Отправка запроса с пустым телом или синтаксически некорректным JSON (`"{not json"`) возвращает `400 Bad Request`.

### FR-07: Опциональные поля `description` и `arrivalTime.checkOut`
- `[+]` **CL-07.1 (Позитивная):** Создание отеля без полей `description` и `arrivalTime.checkOut` завершается со статусом `201 Created`; в `GET /hotels/{id}` эти поля имеют значение `null`.
- `[+]` **CL-07.2 (Позитивная граничная):** Передача `description: "   "` (только пробелы) нормализуется доменным слоем в `null`.
- `[-]` **CL-07.3 (Негативная граничная):** Передача `description` длиной `4001` символ (превышение лимита `4000`) отклоняется со статусом `400 Bad Request`.

### FR-08: Валидация обязательных полей при создании отеля
- `[+]` **CL-08.1 (Позитивная граничная):** Создание отеля с `address.houseNumber = 1` и длиной `name` = 255 символов проходит успешно (`201 Created`).
- `[-]` **CL-08.2 (Негативная):** Отсутствие вложенных объектов `address`, `contacts` или `arrivalTime` возвращает `400 Bad Request` со списком ошибок в `$.errors`.
- `[-]` **CL-08.3 (Негативная):** Передача `name: " "`, `address.houseNumber: 0` и `contacts.email: "not-an-email"` возвращает `400 Bad Request` с ошибками по всем трём полям.

### FR-09: Валидация и сериализация времени `HH:mm` (`ArrivalTimeDto`)
- `[+]` **CL-09.1 (Позитивная граничная):** Граничные значения времени `"00:00"` и `"23:59"` принимаются и возвращаются в формате `"HH:mm"`.
- `[-]` **CL-09.2 (Негативная):** Передача невалидного времени `"25:00"`, `"14:60"` или `"2pm"` возвращает `400 Bad Request`.
- `[-]` **CL-09.3 (Негативная):** Передача `arrivalTime` без обязательного поля `checkIn` (`{"checkOut": "12:00"}`) возвращает `400 Bad Request`.

## Модуль 3: Управление удобствами отеля (`Presentation: HotelAmenityController` & `Domain: Amenity`)

### FR-10: Привязка списка удобств к отелю (`POST /property-view/hotels/{id}/amenities`)
- `[+]` **CL-10.1 (Позитивная):** Передача JSON-массива `["Free parking", "Free WiFi"]` возвращает `200 OK` и полную карточку отеля с привязанными удобствами.
- `[+]` **CL-10.2 (Позитивная граничная):** Передача пустого массива `[]` возвращает `200 OK` без изменения текущих удобств отеля.
- `[-]` **CL-10.3 (Негативная):** Передача JSON-объекта `{"a": 1}` вместо массива, пустой строки `[" "]` или строки длиной `256` символов возвращает `400 Bad Request`.

### FR-11: Нормализация, регистронезависимая дедупликация и порядок удобств
- `[+]` **CL-11.1 (Позитивная):** При отправке `["  Free   WiFi ", "Concierge", "free wifi"]` сохраняются ровно 2 удобства `["Free WiFi", "Concierge"]` в порядке первого добавления.
- `[+]` **CL-11.2 (Позитивная межсущностная):** При добавлении `"free wifi"` ко второму отелю переиспользуется существующая запись в таблице `amenity` с каноническим именем `"Free WiFi"`.
- `[-]` **CL-11.3 (Негативная / Стресс):** Конкурентная отправка нового удобства двумя потоками одновременно выявляет состояние гонки `DEF-01` (`500 Internal Server Error` при нарушении `uq_amenity_normalized_name`).

## Модуль 4: Многокритериальный поиск (`Presentation: SearchController` & `Infrastructure: HotelSpecifications`)

### FR-12: Поиск по `name`, `brand`, `city`, `country`, `amenities` без учёта регистра
- `[+]` **CL-12.1 (Позитивная):** Поиск `GET /search?name=double` находит `"DoubleTree by Hilton Minsk"` по частичному регистронезависимому совпадению.
- `[+]` **CL-12.2 (Позитивная):** Поиск `GET /search?city=minsk&brand=hilton&country=belarus` находит отель по точному регистронезависимому совпадению атрибутов.
- `[-]` **CL-12.3 (Негативная):** Поиск по части названия города `GET /search?city=min` возвращает пустой список `[]`, так как для `city` требуется полное совпадение.

### FR-13: Комбинирование фильтров по `AND` и форматы передачи `amenities`
- `[+]` **CL-13.1 (Позитивная):** Повторные параметры `?amenities=Free%20WiFi&amenities=Concierge` и список через запятую `?amenities=Free%20WiFi,Concierge` возвращают только отели, обладающие обоими удобствами одновременно.
- `[+]` **CL-13.2 (Позитивная):** Вызов `GET /search` без параметров возвращает все отели каталога.
- `[-]` **CL-13.3 (Негативная):** Если хотя бы один из фильтров в комбинации `AND` не совпадает (`?city=Minsk&country=Russia`), возвращается пустой список `[]`.

### FR-14: Экранирование спецсимволов SQL `LIKE` (`%`, `_`, `\`)
- `[+]` **CL-14.1 (Позитивная):** Если в названии отеля присутствует символ `%` или `_`, поиск по этой подстроке находит именно этот отель.
- `[-]` **CL-14.2 (Негативная):** Запрос `GET /search?name=%25` (символ `%`) не возвращает все отели базы, а ищет буквальный символ `%` (возвращает `[]`, если такого символа в именах нет).

## Модуль 5: Аналитические гистограммы (`Presentation: HistogramController` & `Application: HistogramService`)

### FR-15: Построение гистограмм по `brand`, `city`, `country`, `amenities`
- `[+]` **CL-15.1 (Позитивная):** Запросы `GET /histogram/brand`, `/histogram/city`, `/histogram/country`, `/histogram/amenities` возвращают `200 OK` и корректные количества отелей, отсортированные по ключу по алфавиту.
- `[+]` **CL-15.2 (Позитивная):** Параметр пути регистронезависим (`GET /histogram/City`, `GET /histogram/AMENITIES` возвращают `200 OK`).
- `[-]` **CL-15.3 (Негативная / Граничная):** На пустой базе данных `GET /histogram/city` возвращает `200 OK` и пустой объект `{}` без ошибок `NullPointerException`.

### FR-16: Обработка неподдерживаемых параметров гистограммы
- `[+]` **CL-16.1 (Позитивная проверка сообщения):** В поле `detail` ответа `400 Bad Request` явно перечислены все поддерживаемые параметры: `"brand, city, country, amenities"`.
- `[-]` **CL-16.2 (Негативная):** Запрос `GET /histogram/stars` или `GET /histogram/price` возвращает `400 Bad Request` (`application/problem+json`).

## Модуль 6: Безопасность, контроль доступа и логирование (`HotelManagementController` & `GlobalExceptionHandler`)

### FR-17: Аутентификация, защита закрытой зоны и предотвращение IDOR
- `[+]` **CL-17.1 (Позитивная):** `POST /auth/login` с валидными учётными данными возвращает `200 OK` и токен `pv-token-<username>`, с которым владелец получает доступ к `GET /hotels/{id}/management` (`200 OK`) и `DELETE /hotels/{id}` (`204 No Content`).
- `[-]` **CL-17.2 (Негативная — без авторизации):** Прямой переход по URL `GET /hotels/1/management` или `DELETE /hotels/1` без заголовка `Authorization` возвращает `401 Unauthorized`.
- `[-]` **CL-17.3 (Негативная — IDOR):** Попытка пользователя `bob` обратиться к `GET /hotels/1/management` или `DELETE /hotels/1`, принадлежащему пользователю `alice` (подмена `id=2` $\rightarrow$ `id=1`), возвращает `403 Forbidden`.
- `[-]` **CL-17.4 (Негативная — утечка деталей):** Ответы `400`, `401`, `403`, `404`, `500` не содержат строк `java.lang`, `org.springframework`, `org.hibernate` или текста SQL-запросов.
